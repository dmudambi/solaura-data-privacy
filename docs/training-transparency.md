# Training & Dataset Transparency

**How Solaura's AI works today, and how the de-identified research corpus relates to improving Solaura's models.**

> Written for therapists, clinicians, clients, and outside readers who want to know what data does and does not inform Solaura's AI.

*Updated 2026-09-26. The previous version of this document (2026-09-22) said that user sessions were not collected as training data. That statement is superseded by the opt-in research corpus described below. See [archive/README.md](archive/README.md).*

## Summary

- **Session debriefs today (Live):** insights are generated by commercial foundation models (OpenAI, as documented on 2026-09-22) guided by engineered prompts. Generating a debrief does not change any model's weights.
- **Model improvement (Rolling out):** Solaura is building a **de-identified research corpus** from sessions where **both the client and the therapist have opted in**. The corpus will be used to improve Solaura's **internal models for understanding and supporting emotional states**. This may include training or fine-tuning Solaura's own models on de-identified text.
- **Sessions without both opt-ins are never used** for model improvement.

## How debriefs are generated today (Live)

| Approach | Description |
|----------|-------------|
| **Prompt engineering** | Detailed system prompts guide a foundation model to draft session insights |
| **Litmus inventory evaluation** | Prompts are tested against internally developed evaluation scenarios for quality and safety |
| **Foundation model API** | Commercial LLM APIs (OpenAI) that were trained by their provider on the provider's own data |

Per OpenAI's API data usage policy, API inputs are not used to train OpenAI's models by default. See [OpenAI's data usage policy](https://openai.com/policies/api-data-usage-policies). Solaura cannot independently verify the provider's internal practices.

## How the research corpus is used (Rolling out)

| Question | Answer |
|----------|--------|
| What goes in? | Conversation text from sessions where **both** client and therapist opted in, after automated removal of identifiers, generalisation of quasi-identifiers, a residual-PII rescan, and random human review |
| What does it improve? | Solaura's internal models for understanding and supporting emotional states |
| Is it linked to people? | No. There is no bond ID, user ID, session ID, exact timestamp (week bucket at most), or mapping table. Which bond produced a conversation is never recorded. |
| Can it be withdrawn? | Consent can be withdrawn at any time for **future sessions**. Saved contributions cannot be individually deleted because the link to the contributor no longer exists. |
| Is it anonymous? | **No.** It is de-identified. Automated scrubbing can miss context clues. |
| Is it shared outside Solaura? | **Not today.** No corpus data has been shared, licensed, or sold, and there are no research partners. Licensing to vetted research organisations is a planned future use that would need a second, separate opt-in from both client and therapist, plus the safeguards in [Section 5 of the corpus design](deidentified-research-corpus.md#5-planned-future-use-licensing-to-vetted-research-organisations). |

Full design: [deidentified-research-corpus.md](deidentified-research-corpus.md)

## What we do NOT do

| Practice | Position |
|----------|----------|
| Using sessions without both opt-ins for model improvement | ❌ Not done |
| Storing raw, un-scrubbed transcripts in the corpus | ❌ Not done. Scrubbing happens before storage. |
| Keeping a link from corpus records back to people, accounts, sessions, or bonds | ❌ Not done |
| Sharing, licensing, or selling corpus data to outside parties today | ❌ Not done. Planned for the future only, with separate opt-in and safeguards. |
| Calling the corpus "anonymous" | ❌ Not claimed |
| Claiming HIPAA compliance | ❌ Not claimed. See [Legal Notes](legal-notes.md) |
| Publishing accuracy metrics, certifications, or audits for de-identification | ❌ None claimed |

## Evaluation domains

Prompts were tested against scenarios in these broad conversation domains:

| Domain category | Description |
|-----------------|-------------|
| **Personal reflection** | Self-exploration of life events, decisions, and feelings |
| **Therapy-adjacent debrief patterns** | Structured reflection formats similar to session summaries |
| **Goal-oriented dialogue** | Setting and working toward personal objectives |
| **Emotional processing** | Identifying and exploring emotional states |

> These are broad categories. Evaluation uses internally developed litmus scenarios. If specific public datasets are used, this section will name them.

## How Solaura uses AI in practice

Solaura Therapy is a **clinician support tool**. It does not replace clinical judgment.

| Feature | How it works |
|---------|--------------|
| **Session debriefs** | AI drafts summaries and insights from session transcripts |
| **Clinician review** | Clinicians review all AI-generated content before it is used |
| **Edit / reject / approve** | Clinicians can edit, reject, or approve any AI-generated insight |
| **Private until shared** | AI insights stay private to the clinician until the clinician shares them |

```
Session → Transcript → AI drafts insight → Clinician reviews → Edit / Reject / Approve → Share with client (if approved)
                │
                └─ Only if client AND therapist opted in:
                   de-identify → rescan → separate corpus (no link back)   [Rolling out]
```

## Terminology

- **Prompt engineering:** writing inputs that guide a pre-trained model. It does not change model weights.
- **Fine-tuning / training:** updating a model's weights with additional data. For Solaura's internal models, only de-identified corpus data from double-opted-in sessions is intended for this.
- **De-identified:** direct identifiers removed and quasi-identifiers generalised. It is **not** the same as anonymous.
